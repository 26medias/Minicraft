# Fly Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the player press **F** to toggle a fly mode (gravity off, fly at 2× walk speed by default) with `Space`/`Shift` for up/down and `=`/`-` to step through five speed tiers, shown on a small HUD pip meter.

**Architecture:** Three layers. (1) `Player` gains `flying: boolean` and `flySpeedTier: number` fields plus `toggleFly()` / `adjustFlySpeed(±1)` methods; `update()` skips gravity and scales speed when flying. (2) `keybindings.data.ts` gets five new rebindable actions. (3) `Hud.setFlySpeed(tier | null)` shows a 5-pip meter above the hotbar; wired from the main tick loop.

**Tech Stack:** TypeScript, Three.js, Vitest.

Source spec: `docs/superpowers/specs/2026-04-21-fly-mode-design.md`.

        const p = new Player([100, 60, 100]);
        p.toggleFly();

        expect(p.vy).toBe(0);

```typescript
import * as THREE from 'three';
import type { World } from '../engine/world/world';
import { moveWithCollisions } from '../engine/physics/collision';
import type { BlockId } from '../data/blocks.data';

const WALK_SPEED = 5;      // blocks/sec
const JUMP_SPEED = 8;      // blocks/sec, initial upward velocity
const GRAVITY = 24;        // blocks/sec^2
const SIZE: [number, number, number] = [0.6, 1.8, 0.6];
const EYE_HEIGHT = 1.6;
const FLY_TIER_MIN = 1;
const FLY_TIER_MAX = 5;
const FLY_TIER_DEFAULT = 2;

export type Keys = {
    forward: boolean;
    back: boolean;
    left: boolean;
    right: boolean;
    jump: boolean;
    flyUp: boolean;
    flyDown: boolean;
};

export class Player {
    position: [number, number, number];
    vy = 0;
    grounded = false;
    hotbar: BlockId[] = [];
    selected = 0;
    flying = false;
    flySpeedTier = FLY_TIER_DEFAULT;

    constructor(spawn: [number, number, number]) {
        this.position = spawn;
    }

    eyePosition(): [number, number, number] {
        return [this.position[0], this.position[1] + EYE_HEIGHT, this.position[2]];
    }

    toggleFly() {
        this.flying = !this.flying;
        this.vy = 0;
    }

    adjustFlySpeed(delta: number) {
        if (!this.flying) return;
        this.flySpeedTier = Math.max(
            FLY_TIER_MIN,
            Math.min(FLY_TIER_MAX, this.flySpeedTier + delta),
        );
    }

    update(
        dt: number,
        world: World,
        keys: Keys,
        forward: THREE.Vector3,
        right: THREE.Vector3,
    ) {
        let ix = 0, iz = 0;
        if (keys.forward) { ix += forward.x; iz += forward.z; }
        if (keys.back) { ix -= forward.x; iz -= forward.z; }
        if (keys.left) { ix -= right.x; iz -= right.z; }
        if (keys.right) { ix += right.x; iz += right.z; }

        const mag = Math.hypot(ix, iz);
        if (mag > 0) {
            ix /= mag; iz /= mag;
        }
        const speed = this.flying ? WALK_SPEED * this.flySpeedTier : WALK_SPEED;
        const vx = ix * speed * dt;
        const vz = iz * speed * dt;

        let vyStep: number;
        if (this.flying) {
            let vy = 0;
            if (keys.flyUp) vy += speed;
            if (keys.flyDown) vy -= speed;
            this.vy = vy;
            vyStep = vy * dt;
        } else {
            this.vy -= GRAVITY * dt;
            if (keys.jump && this.grounded) this.vy = JUMP_SPEED;
            vyStep = this.vy * dt;
        }

        const r = moveWithCollisions(world, this.position, SIZE, [vx, vyStep, vz]);
        this.position = r.position;
        this.grounded = r.grounded;
        if (r.vy === 0) this.vy = 0;
    }
}
```

## Task 3: Wire the new actions through `main.ts`

**Files:**
- Modify: `src/main.ts`

**Context:**
- `main.ts:90` constructs the `Keys` literal passed to `GameLoop`. After Task 2 it's missing `flyUp` and `flyDown` — fix that first to unblock the typecheck.
- `main.ts:95-124` is the single `keydown`/`keyup` dispatcher. Each action maps into `keys` (held state) or is edge-triggered via the `if (down) { ... }` branch. Slot keys already use the edge-triggered pattern inside `default:`. The new edge-triggered actions (`toggleFly`, `flySpeedUp`, `flySpeedDown`) follow the same pattern.
- `flyUp` and `flyDown` are held-state, like `forward`/`back`.
- `Space` is bound to both `jump` and `flyUp` by default. The dispatcher matches on `e.code` → `Action` via `keyToAction`, and each `code` maps to exactly one `Action`. So a `Space` keydown fires exactly one action — whichever `jump` or `flyUp` appears *later* in `Object.entries(opts.keybindings)` wins. To handle this cleanly, we set the relevant field (`keys.jump` OR `keys.flyUp`) based on `Player.flying` at event time rather than pre-binding two actions to one key. Simpler: **only one of `jump` or `flyUp` may be bound to a given key at any given keydown** — we satisfy this by setting BOTH `keys.jump` and `keys.flyUp` from the `Space` event regardless of which action the key resolves to, then letting the Player state machine pick which one matters. Concretely: when a key resolves to `jump`, set both `keys.jump = down` and `keys.flyUp = down`; when it resolves to `flyUp`, set both as well. Same for ShiftLeft / `flyDown` — set `keys.flyDown = down` either way.

  Rationale: cleaner than introspecting `player.flying` in the input layer; the Player state machine already gates which field it reads.

```typescript
        const onKey = (down: boolean) => (e: KeyboardEvent) => {
            const a = keyToAction[e.code];
            if (!a) return;
            switch (a) {
                case 'forward':
                    keys.forward = down;
                    break;
                case 'back':
                    keys.back = down;
                    break;
                case 'left':
                    keys.left = down;
                    break;
                case 'right':
                    keys.right = down;
                    break;
                case 'jump':
                    keys.jump = down;
                    keys.flyUp = down;
                    break;
                case 'flyUp':
                    keys.jump = down;
                    keys.flyUp = down;
                    break;
                case 'flyDown':
                    keys.flyDown = down;
                    break;
                case 'toggleFly':
                    if (down) player.toggleFly();
                    break;
                case 'flySpeedUp':
                    if (down) player.adjustFlySpeed(+1);
                    break;
                case 'flySpeedDown':
                    if (down) player.adjustFlySpeed(-1);
                    break;
                default: {
                    if (down && a.startsWith('slot')) {
                        const n = Number(a.slice(4)) - 1;
                        if (n >= 0 && n < player.hotbar.length) {
                            player.selected = n;
                            hud.setHotbar(player.hotbar, player.selected);

                }
            }
        };

Setting both `keys` fields on either event makes the Player state machine's single source of truth (`this.flying`) decide semantics. Same reasoning does NOT apply to `flyDown` because `ShiftLeft` has no other default meaning.

- [ ] **Step 1: Reload the game**

Navigate to `http://localhost:5173/`, click **New World**, **Create**. Walk a few steps to confirm the dev server is serving the new build.

- [ ] **Step 2: Verify F toggles fly**

Press **F**.
- [ ] Gravity stops — the player no longer falls. `vy` goes to zero the frame you press F (no residual falling motion).
- [ ] Press **F** again. Gravity resumes. If you were airborne, you fall.

- [ ] **Step 3: Verify vertical movement while flying**

Enter fly mode (F). Then:
- [ ] **Space** — ascend. The player climbs at steady speed (no acceleration).
- [ ] **Shift (left)** — descend.
- [ ] Release both — hover.
- [ ] Holding both at once — stationary vertically.

- [ ] **Step 4: Verify horizontal speed in fly mode feels faster than walk**

In fly mode at default tier 2, walking forward (W) should clearly cover ground faster than in walk mode. (2× is the default.)

- [ ] **Step 5: Verify the speed meter**

- [ ] While flying, the 5-pip meter appears just above the hotbar, centered, with **2** pips filled (default tier 2).
- [ ] Press **=** — a third pip fills. Movement is noticeably faster.
- [ ] Press **=** twice more — all 5 pips filled. Max speed.
- [ ] Press **=** again — still 5 pips filled, no further change (clamped).
- [ ] Press **-** repeatedly to drop to 1 pip. Still 1 pip when holding it further.
- [ ] Press **F** to leave fly mode — meter disappears.
- [ ] Press **F** again — meter reappears at the same tier you left it at (persists within the session).

- [ ] **Step 6: Verify collision in fly mode**

Fly directly into a hill or a wall at max speed. The player should stop against the solid face — **no clipping through blocks**. Try ascending into a ceiling: the player should stop at the ceiling.

- [ ] **Step 7: Verify world reload resets fly state**

- [ ] Enter fly mode, crank speed to 5 pips.
- [ ] Close/refresh the tab. Return to the main menu.
- [ ] Click **Continue** and re-enter the world.
- [ ] Confirm the player spawns on the ground, gravity active (not flying), and the speed meter is hidden.
- [ ] Press F. The meter should appear at **2** pips (the default), not 5.

- [ ] **Step 8: Regression scan**

- [ ] Jump still works when walking (Space).
- [ ] Mining still works with per-hardness timing (left-click a block, progress ring, break).
